# FitApp — вебзастосунок для відстеження фітнес-прогресу

Індивідуальний фінальний проєкт. Соціальна платформа, де користувач ставить
фітнес-цілі, отримує нагороди за досягнення та ділиться прогресом зі спільнотою.

## Швидкий старт

Потрібні три процеси: база даних, бекенд і фронтенд.

### Крок 1. Запустити MongoDB

У репозиторії **немає робочого рядка підключення**: `backend/config/keys_dev.js`
містить заглушку, а змінна `MONGO_URI` у `backend/.env` порожня. Тому базу
потрібно підняти самостійно.

**Варіант А — локальна MongoDB (рекомендовано, не потребує акаунтів).**

Завантажте офіційний архів під свою платформу з
`https://www.mongodb.com/try/download/community` (версія 6.x) і розпакуйте
в теку `.mongodb/server` усередині проєкту. Потім:

```bash
mkdir -p .mongodb/data .mongodb/log && .mongodb/server/bin/mongod --dbpath .mongodb/data --logpath .mongodb/log/mongod.log --port 27017 --bind_ip 127.0.0.1 --fork
```

**Варіант Б — MongoDB Atlas.** Створіть безкоштовний кластер і скопіюйте
рядок підключення — він знадобиться на наступному кроці.

### Крок 2. Запустити бекенд

Встановити залежності:

```bash
cd backend && npm install
```

Запустити:

```bash
cd backend && NODE_ENV=production MONGO_URI="mongodb://127.0.0.1:27017/fitapp" SECRET_OR_KEY="local-dev-secret-key" node server.js
```

> **Чому `NODE_ENV=production` на локальній машині?**
> Ключі зі змінних оточення читає лише `backend/config/keys_prod.js`.
> У режимі розробки береться `keys_dev.js`, де замість URI стоїть заглушка.
> Такий запуск не потребує жодних змін у файлах бекенду.

Успішний старт виглядає так:

```
Server running on port 4000
MongoDB Connected
```

### Крок 3. Запустити фронтенд

```bash
cd frontend && npm install && npm run dev
```

Застосунок відкриється на **http://localhost:3000**.

> **Чому потрібен проксі?** Бекенд не має CORS-middleware, тому браузер
> заблокував би прямі запити з іншого порту. Vite проксіює всі запити `/api/*`
> на `http://localhost:4000` — налаштування в `frontend/vite.config.js`.

### Крок 4. Наповнити базу (необов'язково)

Порожня база показує порожню стрічку. Зареєструйте кількох користувачів через
інтерфейс на `/signup` і створіть публікації, або скористайтесь API напряму.

## Змінні оточення

### Фронтенд

Скопіюйте шаблон:

```bash
cd frontend && cp .env.example .env
```

| Змінна | За замовчуванням | Опис |
| --- | --- | --- |
| `VITE_API_URL` | `/api` | Базовий URL API. Для розробки лишайте `/api` — запити підуть через проксі. Для продакшену вкажіть повний URL бекенду. |

### Бекенд

Читаються з оточення (див. `backend/config/keys_prod.js`):

| Змінна | Обов'язкова | Опис |
| --- | --- | --- |
| `MONGO_URI` | так | Рядок підключення до MongoDB |
| `SECRET_OR_KEY` | так | Секрет для підпису JWT |
| `NODEMAILER_*` | ні | Налаштування пошти, для роботи застосунку не потрібні |

## Тестування

```bash
cd frontend && npm test
```

**87 тестів у 10 сюїтах:**

- **юніт-тести функцій** — форматери дат і чисел, валідатори форм, розбір JWT;
- **юніт-тести редюсерів** — повний цикл роботи з цілями, персист у сховищі;

## Розгортання

### Важливо перед деплоєм

Фронтенд без доступного бекенду покаже порожні сторінки й помилки мережі.
Тому розгортати треба **обидві частини**:

1. **База даних** — MongoDB Atlas (безкоштовний рівень).
2. **Бекенд** — Render, Railway або власний сервер. Задати змінні
   `MONGO_URI`, `SECRET_OR_KEY`, `NODE_ENV=production`.
3. **Фронтенд** — Vercel або Netlify. Задати `VITE_API_URL` = повний URL
   розгорнутого бекенду, наприклад `https://fitapp-api.onrender.com/api`.

### Vercel

У репозиторії є `frontend/vercel.json` із перенаправленням для SPA.
При підключенні проєкту вкажіть:

- **Root Directory** — `frontend`
- **Environment Variables** — `VITE_API_URL`

### Netlify

- **Base directory** — `frontend`
- **Build command** — `npm run build`
- **Publish directory** — `frontend/dist`

Перенаправлення для SPA вже налаштоване в `frontend/public/_redirects`.

### CI/CD

`.github/workflows/ci.yml` — на кожен push і pull request виконує перевірку
форматування, лінтинг, тести з покриттям і продакшн-збірку на Node 20 і 22.

`.github/workflows/deploy.yml` — розгортає фронтенд на Vercel після злиття
в основну гілку. Потрібні секрети репозиторію: `VERCEL_TOKEN`,
`VERCEL_ORG_ID`, `VERCEL_PROJECT_ID`, `VITE_API_URL`.
